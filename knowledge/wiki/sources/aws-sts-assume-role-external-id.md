## Why this source

Closes the AWS STS/IAM cross-account gap identified in the Decision 0014 Phase A review. The Platform MCP Server spans multiple AWS accounts. AssumeRole with external ID is the IAM mechanism that prevents the confused deputy problem in multi-tenant, cross-account access — directly relevant to a centralized platform server acting on behalf of multiple product accounts.

## What it covers

AWS IAM role assumption for third-party cross-account access, specifically the external ID mechanism that prevents the Confused Deputy problem. Covers: the attack scenario, when external ID is required vs. optional, trust policy configuration (`sts:ExternalId` condition), AssumeRole API call with ExternalId parameter, external ID format constraints, and security recommendations.

## Key claims

- The external ID's primary function is to prevent the Confused Deputy problem — where a third-party service is manipulated into accessing a customer's resources without authorization. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- External ID is **required** when a third party manages multiple AWS accounts and uses the same IAM role mechanism for all. Without it, an attacker can provide any customer's role ARN and the third party would assume it. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- Trust policy condition: `{"StringEquals": {"sts:ExternalId": "Unique ID Assigned by Example Corp"}}` in the `Condition` block of the trust policy. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- AssumeRole API call includes `--external-id CUSTOMER_EXTERNAL_ID`; if absent or incorrect, the call fails. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- External ID is **not a secret** — anyone with IAM describe-role permission can view it. It proves the caller is acting on that specific customer's behalf, not that the caller is trusted per se. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- External IDs are generated by the **third party** (not the customer) to ensure global uniqueness across all their customers. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- Format: min 2 chars, max 1,224 chars, alphanumeric + `+`, `=`, `,`, `.`, `@`, `:`, `/`, `-`. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- Recommendation: test AssumeRole with and without the external ID after a customer configures a role. If it succeeds without it, do not store that role ARN — prompt the customer to add the ExternalId condition. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
- AssumeRole returns temporary security credentials (access key ID, secret access key, session token) — never long-term IAM user credentials. [raw/sources/aws-sts-assume-role-external-id-2026-05-04.md]
